# 抬头标注协议（草稿，请按课题组定义修订后再开始标注）

> 这是"什么算抬头"的操作性定义，是整个验证实验的地基：标注 GUI 里的每次按键都以此为据。
> 请和导师确认后修订本文件，修订后再开始标注；标注中途改口径会导致前后不一致。

## 1. 帧级标签定义

| 键 | 标签 | 定义 |
|---|---|---|
| 1 | 抬头 | 头部背面（头顶）与鼻尖连线明显朝上，鼻尖高于常态平视位、下颌抬起，进入"仰望"姿态 |
| 0 | 非抬头 | 平视、低头、嗅探、理毛、走动、转向等一切其他状态 |
| 9 | 无法判断 | 关键点明显飞出身体/严重遮挡/画面歧义，该帧不参与训练与评估 |

## 2. 判定细则（边界情况）

1. **小幅嗅探点动不算抬头**：鼻子朝上但幅度小、瞬间即回（<0.15 s）仍标 1（帧级标注只管姿态，
   持续时间过滤交给状态机与 RF 的时序特征），但"角度在阈值附近、肉眼看不出鼻尖明显朝上"的帧标 0。
   简言之：**看姿态像不像仰望，不看持续时间**。
2. **连续抬起**：中间没回到平视的连续抬头，每帧仍标 1（次数合并交给事件级分析）。
3. **侧身/歪头导致的假角度**：鼠转身、理毛时鼻-头连线角度异常但鼻尖并不朝上 → 标 0。
   这类帧是规则法的主要误差来源，也是 RF 基线的价值所在，请务必如实标注。
4. **双视角画面**：只判断模型追踪的那只鼠所在视角（关键点画在哪只身上就判断哪只）。
5. **两种情况都说得通时**：倾向标 0（宁可漏检、不可放宽），保证正类纯度。

## 3. 与事件级金标准的关系（一次标注两用）

帧级标签聚合成连续段后即为事件级金标准，可直接用于第一点缺口（评分者间 κ、事件级 P/R/F1）：
- 单人标注 → 可算系统 vs 人工的准确率；
- 两人独立标注同一批帧 → 另可算评分者间 Cohen's κ（建议至少 2 段视频做双人）。

## 4. 标注流程

1. `python label_gui.py --annotator 你的名字`
2. 每帧看图按键：1 / 0 / 9，建议正确按 Enter 快进，按 ← 回上一帧改判
3. 标注实时保存，可随时 q 退出、随时续标
4. 全部约 680 帧（每鼠 170 帧），预计 2–4 小时；建议分 2–3 次完成，避免疲劳漂移
5. 标完后：`python train_rf.py`、`python shap_analysis.py`
